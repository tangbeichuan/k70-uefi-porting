# 02 · 系统架构与启动链路

## 整条链

```
ABL (原厂 UEFI bootloader)
  └─ fastboot boot / boot 分区 → 解包 boot.img
       ├─ BootShim (192/224 B)            把 FD 拷到 0xA7100000 并跳转
       ├─ SILICIUM_UEFI.fd (≤4 MiB)       Mu-Silicium 固件卷
       └─ vermeer.dtb (808 KB)            Android 内核口味 DTB（ABL 会读 splash_region 等）
  └─ SEC → PEI → DXE → BDS
```

## 关键地址与常量

| 名称 | 值 | 说明 |
|---|---|---|
| FD 装载基址 | `0xA7100000` | BootShim 目标，`Resources/Configs/vermeer.toml` 的 `[uefi_fd] base` |
| FD 大小 | `0x300000` → 改 **`0x400000`**（4 MiB） | 3 MiB 顶到上限时 GenFv 报 `ERROR 2000` |
| 帧缓冲 | `0xB8000000`，43 MiB | MemoryMapLib `Display Reserved` |
| DXE Heap | `0xBAB00000 + 0xD1C0000` | 分配日志盘/事件环时注意 <4 GiB 约束 |
| UFS 寄存器 | `0x01D84000`（+0x3000） | 原厂 UFSDxe 要 `0x1D80000 + 0x20000` |
| UFS PHY | `0x01D80000` | 与 UFS 同一窗口 |
| GCC | `0x00100000` | `GCC_USB30_PRIM_GDSCR = +0x0F004` |
| SMMU | `0x15000000`（span 0x80000） | SMMU-500；`MemoryMapLib` 第 65 行已映射 |
| DWC3 | `0x0A600000`（size 0xD000） | USB 控制器；QSCRATCH `0x0A6F8800` |
| QUSB2 PHY | `0x088E2000` | USB2 PHY（0x400） |

## 构建链路

```
vermeerPkg/vermeer.dsc       组件、库、PCD
vermeerPkg/vermeer.fdf       FV 布局（!include Include/APRIORI.inc / DXE.inc / RAW.inc）
vermeerPkg/Include/*.inc     派发顺序（vendor INF 只能写 APRIORI.inc，写进 DXE.inc 会重复 → GenFv ERROR 2000）
vermeerPkg/FdtBlob/*.dtb     塞进 FV 的设备树（provider 从这里读）
```

构建命令：

```bash
python3 build_uefi.py -d vermeer -m 0 -r DEBUG
# 产物：Build/vermeerPkg/DEBUG_CLANGPDB/FV/SILICIUM_UEFI.fd
```

打包（`pack_keys.sh` 的精简说明）：

1. `BootShim.bin`（含/不含色块版）与 FD 做 `gzip`，拼成 kernel；
2. 附 `vermeer.dtb`；
3. `mkbootimg.py --header_version 1` → `Mu-vermeer-<tag>.img`；
4. 校验 shim 头里的 `image_size` 与 FD 实际大小一致（否则打包脚本断言失败）。

## 派发顺序（重要）

- `Include/APRIORI.inc` 是**唯一**可以写 vendor INF 的地方（被 `vermeer.fdf:82` 在 FV 段内 include）。
- 自研驱动插入位置决定行为：
  - 早期 provider（`VermeerDtbExtnDxe`）放在 `PCD/Dxe/Pcd.inf` 之后 → 早于所有厂商驱动；
  - 菜单（`VermeerMenuDxe`）放在末尾 → 能用 `ConOut/ConIn`，但**永不返回**会挡住后面的驱动。
- **每轮构建脚本都会重写 dsc/fdf/APRIORI**，所以任何"手工改完再编译"的补丁必须放进构建脚本，否则会被覆盖。
