# 07 · 踩坑清单与工程规则

> 每一条都是真机上付出过刷机次数换来的。

## 构建系统

1. **`Platforms/Xiaomi/vermeerPkg/` 不被 git 跟踪** —— `git checkout` 救不回来，改之前一定备份。
2. **每轮构建都会重写 `vermeer.dsc` / `vermeer.fdf` / `Include/APRIORI.inc`**：手工改完再编译会被覆盖 → 所有改动必须写进构建脚本（`run_keysNNN.sh` / `patch_*.py`）。
3. **vendor INF 只能写在 `Include/APRIORI.inc`**；同时写进 `Include/DXE.inc` 会 `GenFv: ERROR 2000 … same file GUID`。
4. **派生脚本的 `build_keysNNN.sh` 名字不会自动改**：`sed s/keys1NN/keys1MM/` 之后要再 `sed -i 's|bash build_keysNNN.sh|bash build_keysMMM.sh|'`，否则编出来的镜像 **sha 和上一版一模一样**（我们曾连续 6 次构建同一个镜像）。
5. **DROP token 机制会累积 `# [keys47-drop]` 前缀**，下轮把它当原文件继续注释 → 列表变更"不生效"。派生时要先剥前缀。
6. **3 MiB FD 上限**：加模块后 `GenFv ERROR 2000` 多半是顶到上限，改 `Resources/Configs/vermeer.toml` 的 `[uefi_fd] size = 0x400000`，并**重编 BootShim**（`Makefile` 只依赖 `.S`，改 FD_SIZE 不会自动重编，必须 `rm -f BootShim.elf BootShim.bin`）。
7. **在压缩的 FD 里 grep 字符串恒为 0 命中**：必须查 `Build/vermeerPkg/DEBUG_CLANGPDB/FV/FVMAIN.Fv`（或 `FVMAIN.Fv.txt` / `Guid.xref`）。
8. **`gates.py` 会重建 dsc 组件块**：任何"把驱动加进 dsc"的脚本必须排在 `gates.py keyprobe` **之后**执行。

## PEI / 内存映射

9. **PEI 的 `MemoryMapLib.c` 静态表加错一条会直接卡在 `MMU: enabled`**（连 `Loading DxeCore` 都没有）。
10. **`gDS->AddMemorySpace` 只登记 GCD，不建立 CPU 页表** —— 想在 DXE 里访问新的 MMIO 窗口，必须改 PEI 静态表。
11. **UFS 窗口 `0x1D80000` 原本不在任何区段里**（`CRYPTO0 0x1DC0000` 与 `CORE_TOP_CSR 0x1F00000` 之间是空洞）。
12. 扩大已有区段（把 `CRYPTO0` 起点提前到 `0x1D80000`）比新增区段更安全。

## DXE / 驱动

13. **新增独立 FV 模块会改变布局，可能直接卡在 `MMU: enabled`**；把代码内嵌进已有模块（provider / Menu / LogDisk）更稳。
14. **`Menu` 永不返回** → 排在它后面的驱动不会加载；诊断/日志盘必须放在 Menu 之前。
15. **INF 缺 `UefiDriverEntryPoint` → `lld-link: undefined symbol: _ModuleEntryPoint`**；缺 `DxeServicesTableLib` → `no member named 'SetMemorySpaceAttributes'`；缺 `DxeServicesLib` → `undefined symbol: GetSectionFromAnyFv`。
16. **`-Werror,-Wunused-function`** 会拦住"留着备用但没调用"的函数：用 `if (mFlag == 0) { F(); }` 之类保持引用。
17. **`Say()` 的输出是 UTF-16**：用 `strings`/`grep` 在 FV 里搜 ASCII 找不到，要用 `'[TAG]'.encode('utf-16-le')` 搜。

## 显示 / 输入

18. **GOP 整屏清屏会把控制台文字盖掉**，看起来像"黑屏崩溃" —— 诊断版本要么不清屏，要么只画一条横幅。
19. **`SimpleFbDxe` 在 FV 里但 DxeCore 不派发**（`[Depex] TRUE` 也没用）→ 用 `GetSectionFromAnyFv + LoadImage + StartImage` 手动拉起，且**只拉一次**（重复 StartImage 会 ASSERT `Already started`）。
20. **系统里有多个 `SimpleTextIn`**（实测 2–4 个）：`gST->ConIn` 可能恰好是不带货的那个 → 必须 `LocateHandleBuffer` 枚举全部实例逐个 `ReadKeyStroke`。
21. **`ConIn`/`ConOut` 在早期 `gST` 里还是 NULL**：早于 `ConSplitterDxe` 派发的驱动读不到，只能靠 `FrameBufferSerialPortLib` 的 DEBUG 输出。

## USB（DWC3）

22. **不要写 `DCTL.CSFTRST`**：会把 `GUSB2PHYCFG` 打回 SUSPHY，设备从主机消失。
23. **DWC3 偏移容易错 4 字节**：`DCFG=0xC700 / DCTL=0xC704 / DEVTEN=0xC708 / DSTS=0xC70C / GUSB2PHYCFG=0xC200 / GCTL=0xC110 / GSTS=0xC118 / GSNPSID=0xC120`（用 `GSNPSID=0x5533…` 自检）。
24. **事件环 `GEVNTSIZ` 用 `0x80001000`（masked）**，`DEVTEN=0x1277`，事件环地址必须 `<4 GiB` 且 4 KiB 对齐。
25. **SID 别混淆**：UFS 0x60、USB 0x40（来自 IORT `NAMEDNODE_USB0`）。SMMU S2CR `TYPE: 0=translate / 1=bypass / 2=fault`。

## 调试方法

26. **`fastboot boot` 只是内存启动**，不写分区；失败长按电源键即可。
27. **Windows 侧最有用的证据是 `Get-PnpDevice` 的 `VID_0000&PID_0002`**（描述符请求失败 = D+ 已上拉、主机在枚举），比屏上日志更直接。
28. **拍照判读技巧**：`System.Drawing` 旋转 + 定點裁切放大 3–4 倍，能把 720p 照片里的小字读清（脚本见 `scripts/img-rotate-crop.ps1`）。
29. **串口不可用**：`PcdSerialRegisterBase=0x09000000` 是 QEMU 遗留，真机没有；`UsbCdcEcm` 是主机侧网卡，不是虚拟串口。
